# 完整模型与常见问题

## 1. 完整数据流

```text
src token
  -> Embedding
  -> PositionalEncoding
  -> Encoder
  -> memory

tgt token
  -> Embedding
  -> PositionalEncoding
  -> Decoder(..., memory, ...)
  -> Generator
  -> log_softmax
  -> 输出形状 [batch, seq, vocab_size]
```

## 2. 输出层做了什么

解码器输出仍然是 `[batch, seq, d_model]` 的向量。要预测下一个 token，需要把它映射到词表空间：

```python
self.linear = nn.Linear(d_model, vocab_size)
return F.log_softmax(self.linear(x), dim=-1)
```

所以最终输出是 `[batch, seq, vocab_size]`。训练时通常使用 NLLLoss 或 CrossEntropyLoss；推理时对最后一个位置取 argmax 得到预测 token。

## 3. 本项目为什么不训练

本项目目标是看懂结构，所以用随机 token 和随机张量演示。真正的训练还需要：

- 分词器与词表。
- 训练集和验证集。
- padding mask 和因果 mask 的真实构造。
- 优化器、学习率调度、损失函数。
- 训练循环和推理循环。

这些属于“训练与工程化”，当前版本刻意不展开。

## 4. 常见问题

### Q：为什么输出是 log_softmax 而不是 softmax？

log_softmax 数值更稳定，并且可以直接配合 NLLLoss。两者在预测最大概率 token 时结果一致。

### Q：为什么输入 token id 必须小于词表大小？

`nn.Embedding` 的查找表只有 `vocab_size` 行，索引越界会报错。本项目词表大小是 1000，所以示例 token 都小于 1000。

### Q：为什么示例使用全 0 掩码？

入口脚本和测试只做形状演示，所以暂时传入全 0 掩码；这会让所有位置都被屏蔽，softmax 的结果退化为近似均匀分布，但不影响检查输出形状。真实任务中应使用 `1` 表示允许关注、`0` 表示禁止关注的 padding mask 和因果 mask，具体构造方式见 [`docs/02_注意力机制.md`](./02_注意力机制.md)。

### Q：为什么我的运行结果每次不同？

模型参数是随机初始化的，除非设置 `torch.manual_seed`，否则前向结果会变化。形状和流程是稳定的。
