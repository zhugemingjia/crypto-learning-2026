# 解码器

## 1. 解码器和编码器的区别

编码器主要做“理解”，解码器主要做“生成”。生成必须从左到右逐步进行，所以解码器比编码器多了一个关键机制：掩码。

解码器层包含三个子层：

```text
DecoderLayer
  ├── 掩码自注意力 + 残差连接 + LayerNorm
  ├── 编码器-解码器注意力 + 残差连接 + LayerNorm
  └── 前馈网络 + 残差连接 + LayerNorm
```

## 2. 掩码自注意力

生成第 t 个 token 时，只能看到第 1 到第 t 个 token。掩码矩阵通常是下三角矩阵：

```text
[[1, 0, 0, 0],
 [1, 1, 0, 0],
 [1, 1, 1, 0],
 [1, 1, 1, 1]]
```

其中 1 表示可以关注，0 表示禁止关注。

## 3. 编码器-解码器注意力

这是解码器和编码器建立联系的地方：

- Query 来自解码器当前输入。
- Key、Value 来自编码器输出 memory。

所以模型在生成每个词时，可以回头“看”源语言或源文本。

```python
x = self.sublayers[1](
    x, lambda x: self.src_attn(x, memory, memory, src_mask)
)
```

## 4. 两个掩码的区别

- `src_mask`：源序列的 padding 掩码，用在编码器-解码器注意力中，避免 padding 位置影响结果。
- `tgt_mask`：目标序列的因果掩码，用在掩码自注意力中，防止看到未来。项目约定 `1` 为允许、`0` 为禁止。

本项目的入口和测试暂时使用全 0 掩码，只为演示张量形状，并不代表真实任务的正确配置。实际训练或推理时，`tgt_mask` 至少应使用下三角因果掩码；如果序列含有 padding，还要同时屏蔽 padding 位置。注意力实现会把所有为 0 的位置设为极小分数。

最小的因果掩码示例：

```python
seq_len = tgt.size(1)
tgt_mask = torch.tril(
  torch.ones(seq_len, seq_len, dtype=torch.bool)
).unsqueeze(0).expand(tgt.size(0), -1, -1)
```

```bash
python -m examples.demo_04_decoder
```
